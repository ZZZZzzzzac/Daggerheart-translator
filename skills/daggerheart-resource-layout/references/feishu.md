# 飞书实现与导出检查

用于飞书文档排版。以下是已验证过的实现方式和观察到的限制，不是固定 API 合约；操作前检查当前 CLI 帮助、实际块类型和目标权限。

## 双栏和卡片

- 原生 grid 可承载双栏；每列放完整语义单元，不按字符均分正文。封面、宽表和过长数据块可在 grid 外通栏。
- callout 的浅底色可帮助识别卡片归属，卡名可用容器内的粗体正文段落表示。已用实现不能直接把标题块、图片、grid 或 table 塞入 callout；不要把“容器支持正文”推成“支持任意子块”。
- 图片可放在同一列、对应卡片之前，按列宽定显示尺寸并保持比例。回读确认图片实际位于预期列，而不仅是上传成功。
- 选项与问题用原生无序列表块；能力名用文字片段级加粗。不要用全局“冒号前加粗”替代逐段语义判断。

批量修改前先用少量代表性内容验证嵌套和样式；未支持的组合换成已支持结构，不反复提交同样的无效请求。

## 写入和回读

写前记录目标版本与块结构，保留恢复材料；写后回读全文顺序和块树，再核图片、附件的实际存在与归属。能下载时核对原素材与回读文件的哈希。写入接口支持版本条件时，带上已读取的 revision-id；编辑期间版本改变时先判断他人改动，不盲目覆盖。

正文、图片与附件分别核验：正文块成功不代表附件已迁移；附件已上传不代表读者能在目标文档找到或打开。仅操作当前任务授权的文档，不因缺权限自动改共享设置。

## 在线版与导出不是同一种版面

已观察到自动 PDF 分页会切开高亮卡片，跨页容器的底色边缘可能不足，末行文字可能伸出底色，甚至被下一张卡遮挡。grid/callout 的语义归属正确并不能保证 PDF 不切卡。

- 导出后放大检查每个跨页卡片的页尾、续页首行和底缘；不能只看缩略图。
- 优先调整整卡位置、栏位、图片尺寸或改通栏；必须续排时，在自然边界明确延续关系。
- 已验证的候选修正：在 callout 末尾加一个空正文段落（`<p/>`），并在卡片容器外加原生分隔线（`<hr/>`）。一次完整样本的官方 PDF 经逐页目检，原有末行遮挡消失，分隔线正常，未发现文字截断或覆盖；正文顺序与素材完整性另行核验通过。
- 这项验证只覆盖该样本，长卡仍会自然跨页；卡尾留白加分隔线不是“整卡同页”或“永不截断”的保证。其他文档可试用这一修正，但每次都必须重新导出，检查全部受影响页面，确认没有新遮挡、空白页或挤压。调整内边距等其他做法仍需另验。
- 在线版正常、PDF 仍溢出时分别报告；没有可用修复就保留问题说明，取得用户选择，不悄悄更换交付格式。
