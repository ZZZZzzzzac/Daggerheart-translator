# 翻译抓虫判断与取证

## 核对已给定输入

短文可作为一个完整段落对；长文先核对段落、标题、顺序和一对多/多对一关系。对齐不明时保留疑点，不猜配。未匹配文字显式保留空原文或空译文，避免把漏段藏在格式化过程中。

稳定段落ID用于关联审阅和问题；内容hash由本地脚本生成，防止文本修改后仍沿用旧证据。来源名称、页码、链接等仅在输入已提供时作为辅助定位，不是开始审阅的前提。

每个纳入段落都需实际审阅。没读过的内容保持未审，不能把“没有数字差异”“没有候选”当作已审。用户明确排除的内容记录范围理由，不算已读。

## 语义判断

结合完整句段及必要上下文，逐项核查：
- 主体、对象、指代、因果，以及动作与结果
- 条件、否定、例外、并列/择一、比较关系与限制
- 可以/必须/建议等强制程度，时态、频率、范围与持续时间
- 数字、单位、日期、比例、正负号、专名与交叉引用
- 漏译、增译、旧内容残留、错序、标题/表格关联及格式误读
- 术语、语域与自然表达；合理改写不是错误

数字或术语匹配只是辅助。审阅记录应说明实际检查了哪些含义及为什么有/无问题，不能批量填一条泛泛“已检查”就宣称完成。

Daggerheart内容必须调用 `daggerheart-chinese-writing`，按该skill处理语言与术语，不在本工作流复制领域规则。其他项目遵循用户给定的要求。

## 问题、严重度与复核

通用类别：meaning、omission、addition、terminology、consistency、grammar、style、formatting、alignment、source_issue、other。

严重度按实际影响判断：critical可能造成严重误解；high改变主要事实、条件、行动或结果；medium影响局部理解/使用；low是值得修订的细小问题。不要因关键词命中就自动升级。

每个问题保留稳定finding_id、完整原译文、精确证据、影响与建议。一段可以有多个问题，但同一根因不要重复计数。确认与待核实分开；疑点说明不同解释和缺少的上下文。

独立复核者自行阅读证据后给支持、驳回或待查理由。未经独立支持的候选不包装成已确认。输入本身存在错配、抽取或导入错误时，说明已有证据支持的事实与不确定性，不把忠实于错误输入的译文一概归咎于译者。

## 精准高亮

使用完整文本的Unicode code point半开范围，只标当前问题的具体证据。重复数字或词语不能全文染色。漏译可以只有原文高亮；增译可以只有译文高亮；另一侧留空并说明原因，不制造并不存在的对应片段。

重复段落明确指定选中的出现位置。展示选段与分页不能改字；跨页高亮取对应交集，拼接后必须还原原文本。

## HTML验收

默认一屏一项，核心是原文、现译、问题和建议。上一条、下一条、完成集中在底栏，只有输入自带链接才显示第四个来源操作。全文、关联依据、统计与进度工具按需查看。

长文本明确分页，不靠缩小字号或隐藏溢出假装一屏。保存、导入导出进度只关联正确报告与稳定问题ID。空问题集如实说明覆盖；未审ID和未解决对齐必须可见。

检查长段、重复词语、Unicode、单侧遗漏、跨页高亮、完成/撤销、筛选空结果、刷新、坏进度文件和无链接输入。模拟测试不冒充真实浏览器视觉验收。
