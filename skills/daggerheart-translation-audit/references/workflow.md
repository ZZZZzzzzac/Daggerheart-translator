# 审阅与取证

## 范围和覆盖

范围应由项目文件清单和版本关系共同决定。装备独立结构化文件与正文装备区可能重复，也可能属于不同版本。逐条对照后排除，不用标题相似度批量排除。`partial` 项记录纳入/排除的精确段落，覆盖表仍保留该条。

每条记录至少保留文件 ID、string ID、key、范围判断、审阅状态、reviewer、时间与所用快照版本。无问题也留覆盖记录。报告必须显示：原始总数、排除数、部分纳入数、实际纳入数、已审数、未审 ID。不要把“没有候选”统计为“已审”。

## 语义核查

完整能力段是最低有效上下文；代词、被动效果、跨段条件还需邻段或完整卡牌。逐条核对：
- 谁支付费用，谁获得效果，目标是否扩大/缩小；攻击、反应掷骰与其他行动是否混淆
- 成功/失败、希望/恐惧条件、否定、例外和并列逻辑
- 一次/每次/每回合、冷却、持续时间、可选/强制
- 距离、目标数、骰型、固定加值、生命/压力/希望/恐惧与伤害类型
- 旧版新增/删去的句子、重复段、漏译和不属于本条的译文

数字扫描应识别 dice、负号、阈值、分数和中文数字等，但仅作人工注意线索。排版差异、同义改写和不影响含义的自然中文不是默认缺陷。

## 证据与分类

每个发现有稳定 finding_id；同条可以有多个发现，但避免把同一根因拆成多个计数。严重度与结论状态分别记录：
- critical：显著改变核心判定或可能直接引发严重规则误用
- high：明确改变行动、触发、费用、目标、效果或漏关键规则
- medium：局部规则理解受影响，影响面较窄
- low：确定存在的非关键术语、表述或可用性问题

状态为 confirmed / uncertain / dismissed / resolved / stale。`uncertain` 写出争议两方、还缺什么证据；不能拿置信度高代替证据。`resolved` 要有线上回读后的准确文本、时间和重新语义判断；“审阅完成”是独立 UI 状态。

证据至少含可定位的中英片段、完整上下文、问题与规则影响、具体建议、文件和词条链接。官方文档证据注明版本、页码/节名、URL 与提取方式；多栏、表格、跨页、脚注应查看实际页面。若只查了部分官方 PDF，不能宣称全项目已与官方源对齐。

源文错误分类示例：官方 PDF 中甲列末段误落入乙条的 ParaTranz original；译文忠实跟随错误导入。应保留三层文本并建议修复导入/结构，不单记为“乙条翻译错”。一条可能同时有源文问题与译文问题，分别说明。

## 第二轮与增量

复核记录包含 reviewer、decision（support/reject/uncertain）、reason、时间、证据。审阅者读取原始证据独立判断后，再与第一轮候选比较；对被驳回的候选保留内部审阅记录，默认不混入待修列表。

快照获取时记录的是时间窗口。结束前重新拉全量选定文件，比较 ID 增删和内容/版本/上下文；重新审阅增量与受影响的邻接内容，更新覆盖表和计数。必要时再次回读，直到已知变更均处理或明确记录剩余未核验边界。不要无限追逐活跃项目，也不要把未核验的动态项目称为实时。

## 报告验收

默认打开一屏一项，原文/现译/问题/建议最醒目。完整上下文按需展开，搜索/统计/导入导出等工具收起。保留稳定 ID、自动保存与可导入导出的进度。ParaTranz 打开新标签；离线交互不发写请求。长段落明确分页或进入全文视图，不能缩到难读、截掉关键信息或隐藏溢出假装一屏。

测试典型屏幕、小屏、超长条目、过滤空结果、来回翻页、刷新、导入非法/旧版/其他报告进度、重复ID、HTML特殊字符与恶意脚本字符串。检查进度只与正确报告和发现ID关联，UI“已处理”不会宣称远端已修复。
