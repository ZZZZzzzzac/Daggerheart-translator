# 通用双语审阅与取证

## 先对齐，再判断

输入可以是两份文本、两份文本文件、已配对的段落JSON，或翻译平台导出。记录来源名称、版本/读取时间、内容hash、稳定段落ID与对齐依据。来源链接是可选证据，不是审阅前提。既有技能目录名为兼容安装保留，不限制题材或语言。

短文可将整份原文与译文作为一个pair；较长文件必须先核对段落、标题、顺序与多对一/一对多关系。不能默认第n段永远互相对应。没有对齐的文字不得丢弃：显式保留空原文或空译文的一侧，用于识别增加内容或漏译；分段不能吞掉标点、换行、表格标题或脚注。

每个纳入pair都必须有覆盖记录，包括没有发现问题的段落。尚未实际通读时标为未审，不能根据“没有数字差异”“没有候选”自动改为已审。排除重复版本需记录对应版本/条目与理由；部分纳入需说明精确范围，不因局部重复而排除整项。

## 逐项语义检查

阅读完整句段及必要前后文，先判断两侧传达的意思，再借助项目术语和数值线索：
- 主体、对象、指代与因果，动作与结果是否一致
- 条件、否定、例外、并列/择一、比较关系与限制是否保持
- 可以/必须/建议等强制程度，时态、频率、范围与持续时间
- 数字、单位、日期、货币、比例、正负号、专有名词、交叉引用
- 漏译、多加内容、旧版残留、错序、标题/表格关联、格式导致的误读
- 术语一致性、语域与自然度是否确实影响使用；自然改写不是默认错误

机械扫描只找候选，不能代替语义阅读，也不能将脚本通过称为“AI已经全部审完”。脚本负责对齐、追溯、数据检查和报告渲染；实际语义结论由审阅者作出，保存其身份/角色、日期、理由及证据。

## 分类、证据和复核

一般分类可用 meaning、omission、addition、terminology、consistency、grammar、style、formatting、alignment、source_issue、other。严重度与结论状态独立：
- critical：可能造成安全、义务或核心操作的严重误解；按实际用途判断，不因某个关键词自动升级
- high：明确改变主要事实、条件、行动或结果
- medium：局部理解或使用受影响，影响面较窄
- low：确定存在且值得修订的细小表述、术语或格式问题

状态区分 confirmed、uncertain、dismissed、resolved、stale。置信度不能替代证据。疑点写明两种解释及缺少的上下文；已修必须实际读取新文本并重新判断，不能因有人点击完成就宣称源文件已改。

每个发现有稳定finding_id，可关联同一个pair但避免重复计数同一根因。保留完整原文、现译、精确问题片段、影响、建议和记录hash。候选交独立审阅者先读证据、再判断支持/驳回/待查；没有独立复核时披露，不把未复核候选伪装为已确认。

精准高亮使用完整文本的Unicode code point半开范围。只亮当前问题涉及的证据，重复词语不全局染色。漏译可能只有原文高亮；增加内容可能只有译文高亮；不捏造另一侧文本。重复选段明确定位出现位置，全文不改字，分页后的文本严格可还原。

## 源文和增量

如怀疑OCR、表格串列、导入或版本问题，区分权威/原始文件、抽取/导入原文、当前译文。文档页面、文件hash、页码或节名均可作定位证据，不强迫不存在的公网URL。不能把译文忠实跟随错误导入一概归咎为翻译错误。

交付前重新读取使用的文件或来源；内容、上下文或版本变化时旧审阅过时，即使ID相同也要重新判断。比较新增、删除及变化段落，并检查关联上下文。仅有旧版本时明确截止时间，不声称实时。对齐发生变化也须重新审阅，不通过迁移旧hash“保持已审”。

## HTML验收

默认一屏一项，原文、现译、问题、建议为核心；上一条、下一条、完成集中在固定底栏，有有效来源链接时再显示第四个跳转操作，无链接不展示死按钮。使用来源真实名称；ParaTranz只是其中一种。全文、相关依据、统计和进度工具按需查看。

长文本明确分页，不靠缩小字号或隐藏溢出假装一屏。保留高亮、自动保存/导入导出和稳定ID。无问题时显示空队列和覆盖/截止时间说明，不造一条“无问题”作为发现。覆盖不完整则明确仍有未审项。

验收本地输入/无链接、不同provider、空问题集、长段、重复词语、Unicode、单侧遗漏、跨页高亮、来回翻页、完成/撤销、过滤空结果、刷新恢复、坏进度/其他报告进度与HTML特殊字符。静态或DOM模拟不是实际浏览器视觉验收。
